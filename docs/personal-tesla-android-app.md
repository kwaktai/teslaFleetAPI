# 개인용 테슬라 안드로이드 앱 메모

상용화하지 않고 **본인 차량만** 쓰는 개인 용도.  
폰은 **차에 상주**하고, 목적은 **전방 과속카메라 경고**.

## 다시 생각한 결론

**폰 키(BLE)는 필요 없다.**  
**카카오내비도 속도·위치용으로는 필요 없다.**  
속도·위치는 **폰 GPS 한 줄**이면 된다.

이미 서버에 같은 전제의 페이지가 있다: [`/speedcam`](../README.md)  
Tesla API와 무관, 휴대폰 GPS만 사용, 전방 700m · 진행 방향 ±45°, 제한속도 +9 km/h에서 차임.

| 넣고 싶었던 것 | 실제 필요한가 | 이유 |
|---|---|---|
| Tesla BLE / 폰 키 | 아니오 | 차는 이미 시동·키 있음. 경고와 무관 |
| 차 내비 목적지 | 아니오 (1차) | “지금 가는 방향 앞 카메라”면 목적지 불필요 |
| 차 드라이브 상태 | 아니오 | P에서 GPS 속도≈0이면 경고 안 남 |
| 차 속도 (Fleet/CAN) | 아니오 (1차) | 폰 GPS 속도로 충분. 고속에선 계기판과 거의 같음 |
| 차 위치 (Fleet) | 아니오 (1차) | 폰 GPS가 더 잦고 지연이 없음 |
| 카카오내비 앱/SDK | 카메라 품질·방향이 최우선이면 | 맵매칭 + 카카오 단속 DB. 속도 센서용이 아님 |
| 카카오맵 REST | 휴게소·충전소 POI | 키워드 `휴게소`, `전기차충전소` / 카테고리 `OL7` |
| 안드로이드 네이티브 앱 | 선택 | `/speedcam`을 브라우저로 켜도 됨. 상주·자동시작이 필요할 때만 앱 |

---

## 왜 카카오내비가 필요해 보였나

카카오내비는 **속도·위치 센서가 아니라** 이미 GPS를 쓰는 완성된 안내 앱이다.  
우리가 필요한 값은 카카오를 통하지 않아도 폰이 바로 준다.

```
폰 GPS → 위도/경도 + 속력 + 진행방향
       → 카메라 DB와 거리/각도 비교
       → 전방이면 경고
```

카카오내비가 하는 일도 본질은 이것이다. 다만 카카오 카메라 DB·음성·구간단속이 더 촘촘할 뿐이다.

### 카카오내비를 그냥 쓰는 경우

테슬라 내비 대신 **그 상주 폰에서 카카오내비로 길을 안내**하면, 앱을 만들 필요 없이 과속 경고가 된다.

테슬라 화면으로만 길을 찾고, 폰은 **경고만** 울리게 하려면 카카오내비는 오히려 안 맞다. 목적지가 두 개가 되고, 화면·음성이 겹친다.

---

## 속도·위치를 차에서 가져올 때

필요한 경우는 하나다. **폰 GPS가 나쁜 거치 위치**(콘솔 속, 금속 아래).

| 소스 | 주기 | 상주 폰 경고에 |
|---|---|---|
| 폰 GPS | 1초 | **기본. 이것만으로 시작** |
| Fleet API | 수 초~슬립 | 지연·과금·슬립. 실시간 경고에 약함 |
| T-2CAN 속도 | 빠름 | 위치는 CAN에 없음. 폰과 브리지 필요 |
| 카카오내비 | — | 센서 공급원이 아님 |

계기판 속도는 GPS보다 조금 높다. `/speedcam`도 그래서 +9 km/h 여유를 둔다. 차 CAN 속도를 굳이 맞출 필요는 없다.

## 추천 순서

1. **지금:** 상주 폰을 GPS 잘 잡히는 곳(대시/윈드실드)에 두고, NAS `/speedcam`을 브라우저로 연다. 공공데이터 CSV를 `speedcam.json`에 넣는다.
2. **상주가 불편하면:** 같은 로직의 안드로이드 앱 (부팅 시 자동 실행, 화면 유지, 큰 글씨, TTS). Play 등록 없음.
3. **GPS가 죽으면 그때:** Fleet 위치 보조 또는 거치 위치 변경. BLE 폰 키는 넣지 않음.
4. **휴게소·충전소:** 카카오 로컬 검색으로 전방 POI만 추가
5. **카메라 방향 오탐이 크면:** 공공데이터에 방면 필드가 있으면 쓰고, 그래도 부족하면 카카오내비 병행

---

## 카카오로 넣을 것: 전방 휴게소 · 충전소

카카오맵 REST에는 **과속카메라 API가 없다.**  
휴게소·충전소는 **장소 검색**으로 된다.

| 필요한 것 | 카카오에서 | 비고 |
|---|---|---|
| 전방 휴게소 | `keyword.json?query=휴게소` + 현재 `x,y` + `radius` | 고속도로 휴게소·일반 휴게소가 섞일 수 있음 |
| 그 휴게소의 충전소 | 같은 좌표 근처 `query=전기차충전소` 또는 카테고리 `OL7` | `OL7`은 주유소+충전소 |
| 충전기 사용 가능 대수 | 카카오 POI에는 거의 없음 | 환경부 공공데이터(KECO)가 맞음 |
| 과속카메라 목록 | **제공 안 함** | 카카오내비 앱 내부 DB |

전방만 보려면 지금 `/speedcam`과 같이 한다.  
GPS 위치 → 반경 검색 → **진행 방향과 방위각이 맞는 것만** 표시.

속도·위치는 여전히 폰 GPS. 카카오는 **장소 이름·좌표**만 가져온다.

---

## 들은 대로: 방향은 카카오가 더 정확하다

맞다. 다만 그게 **GPS 나침반이 좋아서가 아니다.**

| | `/speedcam` (지금) | 카카오내비 |
|---|---|---|
| 방향 | GPS 헤딩 ±45° | **맵매칭** — 도로 링크·방면(서울 방향 등)에 붙임 |
| 카메라 | 좌표 + 제한속도만 `[lat,lng,limit]` | 방면·구간·이동식까지 |
| 반대차선 | 오탐 가능 | 거의 안 울림 |

공공데이터 카메라는 좌표는 있어도 **어느 방면 단속인지**가 비어 있거나 늦다.  
헤딩만 쓰면 고속도로 맞은편 카메라가 전방으로 잡힐 수 있다. 카카오가 정확하다고 느껴지는 이유다.

카카오 **맵 API**를 켠다고 맵매칭이 생기지는 않는다. 맵매칭은 **카카오내비(모빌리티 SDK/앱)** 쪽이다.

그래서 역할을 나눈다.

- **카메라 경고 품질**이 최우선 → 상주 폰에 카카오내비 (만들 필요 없음)
- **테슬라 내비 + 휴게소/충전 안내 + 간단한 카메라** → 폰 GPS + 공공 카메라 + 카카오 장소검색
- 둘을 한 카카오 API로 통일할 수는 없다

공공 카메라와 카카오 단속 정보가 **불일치하는 것은 정상**이다. 카카오 카메라 DB를 API로 받을 방법이 없다.

---

## 권장 조합

```
폰 GPS          → 위치, 속도, 대략 방향
공공 카메라 DB   → /speedcam 경고 (불일치·반대차선 오탐 감수)
카카오 로컬     → 전방 휴게소, 근처 충전소 이름/좌표
환경부 충전 API  → (나중에) 사용 가능 충전기 수
카카오내비 앱    → 카메라·방향이 더 필요할 때만 병행
```
